# 自然な日本語への校正

## 何をするスキルか

日本語の文章を受け取り、**意味を変えずに**不自然さだけを取り除く。

対象とする「不自然さ」は4層ある。上から順に直す（上の層ほど読者への影響が大きい）。

| 層 | 内容 | 参照 |
|---|---|---|
| 1. 文法・破綻 | 主述のねじれ、ら抜き、二重敬語、係り受けの誤り | `references/grammar.md` |
| 2. 翻訳調 | 英語直訳構造、冗長な代名詞、無生物主語、受動態過多 | `references/translationese.md` |
| 3. AI文体 | LLM特有の言い回し、水増しの前置き、定型のまとめ | `references/ai-style.md` |
| 4. 表記 | 漢字ひらがな配分、句読点、数字・記号、表記ゆれ | `references/notation.md` |

出典は `references/sources.md`。

## 大原則

**書き手の意図と情報量を変えない。** 校正であって書き直しではない。情報を足さない、削らない、断定度を勝手に上下させない。

**迷ったら直さない。** 「自分ならこう書く」は不自然さではない。文体の好みと不自然さを混同しない。判断がつかないものは修正せず、「要検討」として提示する。

**根拠を言えない修正はしない。** 各修正には「なぜ不自然か」を1行で言えること。言えないなら文体の好みなので触らない。

## ワークフロー

### 手順1: 文書の設定を確定する

直す前に、次を確定させる。ユーザーの指定がなければ原文から推定し、推定した旨を明示する。

- **文体**: 敬体（ですます）／常体（である）。混在は原則エラーだが、箇条書き内だけ常体、といった意図的な使い分けは許容する
- **読者**: 社内／社外／不特定多数。敬語の水準がここで決まる
- **媒体**: メール、ES・履歴書、技術文書、Web記事、README。表記ルールの厳しさが変わる
- **既存の表記ルール**: リポジトリに `textlintrc`、スタイルガイド、用語集があれば最優先で従う

### 手順2: 機械検出を先に回す

```bash
python3 .claude/skills/natural-japanese/scripts/detect.py <ファイル>
# 標準入力も可
cat draft.md | python3 .claude/skills/natural-japanese/scripts/detect.py -
# JSON で受け取る
python3 .claude/skills/natural-japanese/scripts/detect.py draft.md --json
```

検出器は**機械的に判定できるものだけ**を出す。網羅はしないし、誤検出もする。出力は候補であって確定ではない。必ず原文を読んで採否を決める。

検出器が拾わない層（主述のねじれ、論理の飛躍、段落構成、語彙選択）は自分で読む。

ルール表（`detect.py` の `RULES`）を編集したら、必ず回帰テストを通す。

```bash
python3 .claude/skills/natural-japanese/scripts/selftest.py
```

`scripts/fixtures/unnatural.md` の必須IDが全部出ること、`scripts/fixtures/natural.md` に誤検出が出ないことを確認する。新しいルールを足したら、両方のフィクスチャに例を追加する。

### 手順3: 4層を順に直す

層1（文法）から順に。上の層を直すと下の層の問題が消えることがあるため、順序は守る。

各層の詳細ルールは `references/` を読む。SKILL.md には最頻出のものだけ置く（下記「最頻出15」）。

### 手順4: 検証する

修正後に必ず次を確認する。

1. **情報の同一性**: 原文と修正文を並べ、含まれる情報が増減していないか
2. **断定度**: 「かもしれない」を「である」に変えていないか（逆も）
3. **固有名詞・数字・日付**: 一字一句変えていないか
4. **文体の統一**: 敬体／常体が最後まで揃っているか
5. **検出器の再実行**: 修正で新しい問題が入っていないか

### 手順5: 提示する

原則としてこの形式で返す。

```
## 修正後
（全文）

## 主な修正（重要なものだけ）
- 原文「〜」→ 修正「〜」（理由：冗長／翻訳調／表記）

## 要検討（直していない）
- 「〜」：〇〇の可能性があるが、意図が判断できないため保留
```

修正が3件以下なら差分だけ示す。全文が長い場合はユーザーに全文提示の要否を先に聞く。

## 最頻出15

これだけで大半の不自然さは消える。詳細と例外は `references/` を見る。

| # | NG | OK | 理由 |
|---|---|---|---|
| 1 | 〜することができます | 〜できます | 冗長 |
| 2 | 検討を行う／実施する | 検討する | サ変名詞の空回し |
| 3 | 〜という点が重要です | 〜が重要です | 「という」の水増し |
| 4 | 私は〜と思います（毎文） | （主語を落とす） | 日本語は主語を省く |
| 5 | それは〜です（英語の it） | （指示語を落とす／具体名詞に） | 翻訳調 |
| 6 | この記事はあなたに〜を教えます | この記事では〜を説明します | 無生物主語 |
| 7 | 〜のうちの一つです | 〜の一つです／（丸ごと削る） | one of the の直訳 |
| 8 | 〜を持っています | 〜があります | have の直訳 |
| 9 | 〜して下さい／〜する事／出来る | 〜してください／〜すること／できる | 補助動詞・形式名詞はひらがな |
| 10 | いかがでしたでしょうか／まとめると | （削る） | AI・SEO記事の定型 |
| 11 | 〜と言えるでしょう／ではないでしょうか | 〜です／〜と考えられます | 断定回避の癖 |
| 12 | 見れる／食べれる | 見られる／食べられる | ら抜き（文書では避ける） |
| 13 | お伺いさせていただきます | 伺います | 二重敬語 |
| 14 | 〜における／〜に関して（多用） | 〜の／〜について | 硬い漢語の水増し |
| 15 | 一文が60字超 | 分割する | 読点2個超えたら疑う |

## やらないこと

- **原文にない情報の追加**。「補足すると読みやすい」と思っても足さない。必要なら「追記候補」として別枠で提案する
- **文体の全面変更**。敬体を常体にするのはユーザーの指示があるときだけ
- **専門用語の言い換え**。分野の慣用語は不自然に見えても残す。判断がつかないなら「要確認」を付ける
- **引用部分の修正**。他者の発言、既存文書からの引用は原文どおり
- **コード・コマンド・URL の変更**

## 不明なときの扱い

- 意図が読み取れない文は**直さずに指摘だけする**。推測で書き換えない
- 固有名詞の表記（社名の正式表記など）が不明なら `[要確認]` を付ける
- 業界特有の慣用が絡む判断は「（推測です）」と明示する
