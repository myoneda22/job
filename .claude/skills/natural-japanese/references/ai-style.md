# AI/LLM文体の検出と修正

LLM が書いた日本語には共通の癖がある。文法的には正しいので検出器では拾いきれない。読んで判定する。

なお本ファイルの分類は、既存の文体規範に載っているものではなく、実運用で観察されたパターンの整理である（推測を含む）。個々のルールは絶対ではなく、媒体によっては許容される。

## 1. 水増しの前置き・後置き

内容が何もない定型句。丸ごと削る。

| 削るもの |
|---|
| いかがでしたでしょうか／いかがでしたか |
| まとめると／総括すると／結論から言うと（本当に結論を先に書くなら不要） |
| 〜について解説していきます／〜を見ていきましょう |
| ぜひ参考にしてみてください／ぜひお試しください |
| 素晴らしい質問ですね／なるほど、興味深いですね |
| この点については、以下で詳しく説明します（直後に説明があるなら不要） |
| 本記事では、〜について説明します（見出しが既にそれを言っているなら不要） |

## 2. 断定回避の癖

LLM は語尾をぼかす。責任を取らない文章になり、情報量が落ちる。

| NG | OK |
|---|---|
| 〜と言えるでしょう | 〜です／〜だ |
| 〜ではないでしょうか | 〜です（または疑問なら「〜か」と素直に聞く） |
| 〜かもしれません（根拠があるのに） | 〜です |
| 〜する傾向があると考えられます | 〜する（データがあるなら数字を出す） |
| 一般的には〜とされています | 出典を出して「〇〇によれば〜」 |

**判定基準**: ぼかしが1段落に2回以上出たら削る。ただし**本当に不確かなことをぼかすのは正しい**。根拠があるのにぼかしているものだけ直す。逆に、根拠がないのに断定しているものは「要検証」を付ける。

## 3. 三点セット癖

理由も3つ、メリットも3つ、注意点も3つ。数を揃えるために薄い項目が入る。

**修正**: 実質のある項目だけ残す。1つで足りるなら1つでよい。箇条書きにする必然性がない（項目間に並列関係がない）なら地の文に戻す。

## 4. 過剰な構造化

短い内容に見出し・箇条書き・表を付けて長く見せる。

| 症状 | 修正 |
|---|---|
| 3行の内容に見出しが2つ | 見出しを外して1段落にする |
| 箇条書きの各項目が1文の完全文 | 地の文の連続にする |
| 表の列が「項目／内容」だけ | 表をやめて定義リストか段落に |
| 太字が段落に3箇所以上 | 本当に強調したい1箇所だけ残す |

## 5. 感情の演出

| NG | OK |
|---|---|
| 素晴らしい成果です！ | 目標を12%上回った。 |
| とても重要なポイントです | （重要なら書く位置で示す。形容で示さない） |
| 驚くべきことに | （数字を出す） |
| 感嘆符（！） | 原則使わない（公用文でも「必要な場合に限る」扱い。`sources.md` 参照） |
| 絵文字 | 媒体が明示的に許容している場合のみ |

## 6. 語彙の同語反復・空語

LLM が多用する、内容の薄い語。

`活用する` `最適化する` `効率化する` `実現する` `推進する` `構築する` `シームレスな` `包括的な` `多角的な` `本質的な` `〜という観点から` `〜の重要性` `〜に他ならない` `〜と密接に関係している`

**修正**: 何をするのか具体的に書けるなら書く。書けないなら、その文自体が不要である可能性が高い。

- NG: DXを推進し、業務を効率化することが重要です。
- OK: 請求書の処理を手入力からOCRに変えると、月40時間の作業がなくなります。

## 7. 対句・並列の癖

「〜だけでなく、〜も」「一方で」「〜する反面」が理由なく多い。並列にする実質があるときだけ使う。

## 8. 「という」の連発

`〜という点` `〜ということ` `〜という形で` `〜というもの` — ほぼ削れる。

- NG: 品質を担保するという点が重要だということです。
- OK: 品質の担保が重要です。

## 9. ES・志望動機での典型

このリポジトリの用途（就活）で特に問題になるもの。

| NG | 問題 | 方向 |
|---|---|---|
| 貴社の成長に貢献したいと考えております | 誰でも書ける | 何を、どう貢献するのか具体的に |
| 幼少期から〜に興味を持ち | 定型の導入 | 応募内容と繋がるエピソードから始める |
| チームで協力し、課題を解決しました | 主語が曖昧 | 自分が何をしたのかに限定する |
| 〜という経験を通じて学びました | 学びの内容が抽象 | 行動が具体的にどう変わったかを書く |
| 多くの困難がありましたが、乗り越えました | 中身がない | 困難の中身と対処を1つに絞る |

数字（人数、期間、増減率）を1つ以上入れると定型句が減る。ただし**事実でない数字を作らない**。原文にない数字は絶対に足さない。数字が必要だと判断したら「ここに実績数値を入れるべき」と指摘するにとどめる。
