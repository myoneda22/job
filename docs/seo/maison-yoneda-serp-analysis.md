# 「Maison Yoneda」指名クエリ SEO 分析

対象: 川崎市高津区溝口5 / 東急田園都市線 高津駅 徒歩5分の賃貸物件「Maison Yoneda」
起点: Bing 検索 `Maison Yoneda`
調査日: 2026-08-29

---

## 0. 調査条件と限界（先に明記）

- 本調査環境から `bing.com` / `suumo.jp` / `homes.co.jp` / `athome.co.jp` などへの
  直接 HTTP アクセスは egress ポリシーによりブロックされている（全て接続不可）。
- したがって **Bing SERP の実順位、各ページの title / meta description / 構造化データの
  実装状況は未検証**。本書は、表記ゆれ・言語・サイト指定を変えた複数クエリによる
  インデックス横断調査から再構成した「掲載構造の分析」である。
- 数値順位を要する判断（例: 何位を取れば流入がいくら）は、Bing Webmaster Tools /
  Google Search Console の実データで別途検証が必要。§7 に検証項目を列挙する。

## 1. 結論（3行）

1. 指名クエリ「Maison Yoneda」を取っているのは **SUUMO物件ライブラリーの1ページのみ**。
   他ポータルは全社、建物単位ページを持たず「エリア×駅」一覧しか出ていない。
2. ただし SUUMO のそのページは **住所とアクセスしか無い薄いアーカイブページ**であり、
   独自情報・構造化データ・地図POIのいずれも押さえていない。防御は堅くない。
3. 最大の構造課題は競合ではなく **名前の識別力**。「Maison」＋「Yoneda」は
   一般語＋一般姓の組み合わせで、朝霞市・板橋区の同名物件、および
   Maison Yoshiki Paris / MAISON YONA / 写真家 Tomoko Yoneda と SERP を奪い合っている。
   **「どの Maison Yoneda か」を解決しているページが世界に一つも無い。**

## 2. SERP に何が起きているか — 3つの意図が混線している

指名クエリ 1 本に対して、まったく別の 3 種類の実体が同居している。

| 群 | 実体 | 代表URL |
|---|---|---|
| A. 当該物件 | 川崎市高津区溝口5 の賃貸 | `suumo.jp/library/tf_14/sc_14134/to_1002872484/` |
| B. 同名異物件 | メゾンヨネダ（埼玉県朝霞市北原） | `homes.co.jp/archive/b-19906289/`, Yahoo!マップ POI |
| B. 同名異物件 | メゾン米田（東京都板橋区前野町） | Yahoo!マップ POI |
| C. 別ブランド | Maison Yoshiki Paris / MAISON YONA | Wikipedia / maisonyona.com |
| C. 別人物 | 写真家 Tomoko Yoneda（Maison de la culture du Japon à Paris 展示） | mcjp.fr ほか |
| C. 別人物 | 建築家 Akira Yoneda（Architecton） | fgautron.com ほか |

**SEO 上の意味**

- 検索エンジンから見て「Maison Yoneda」はまだ **エンティティとして解決されていない**。
  Knowledge Graph 上の実体が確定していないため、クエリ意図が分散し、
  どのページも安定した独占を得られていない。
- B 群（同名異物件）は Yahoo!マップに POI として登録されている一方、
  **当該の高津物件はマップ POI が確認できない**。ローカル面が完全に空白。
- 表記ゆれが 3 系統（`Maison Yoneda` / `メゾンヨネダ` / `メゾン米田`）あり、
  どのページもこれを名寄せしていない。

## 4. 各社の SEO 設計を分解する

### 4-1. SUUMO物件ライブラリー — 「在庫型（アーカイブ）SEO」

これが今回唯一の勝者であり、仕組みが最も重要。

- **仕組み**: 2011年12月以降に SUUMO（PC版）へ掲載された物件情報を恒久アーカイブ化。
  募集が終了しても URL が残る。同一物件を新築/中古/賃貸で串刺し表示する設計。
- **狙い**: 「物件名」という超ロングテール指名クエリを、**募集終了後も刈り取り続ける**。
  他社は空室が消えるとページも消えるため、時間が経つほど SUUMO だけが残る。
  今回の状況はまさにその結果。
- **URL 設計**: `/library/ tf_14（都道府県） / sc_14134（市区町村） / to_1002872484（建物ID）`
  階層がそのままパンくずと内部リンクになる、教科書的なファセット構造。
- **タイトル**: `Maison Yonedaの賃貸物件・価格情報【SUUMO】`
  → 建物名を**先頭**に置き、ブランドを【】で末尾に置く。指名クエリへの完全一致型。
  Bing は完全一致タイトルに Google より素直に反応するため、この形が効いている。

**弱点（＝つけ入る隙）**

- コンテンツが薄い。住所・最寄駅・過去の掲載情報のみ。
- 写真、間取り図、設備、管理情報、周辺情報などの独自コンテンツがゼロ。
- 募集がなければコンバージョンにも繋がらず、情報が古いまま放置される。
- 「先に取っているだけ」の状態であり、実体のあるページが立てば入れ替わりうる。

### 4-2. LIFULL HOME'S — アーカイブ型 + ステータス表示

- `/archive/b-{建物ID}/` に加え `/archive/b-{建物ID}/u-{部屋ID}/` の**2階層**を持つ。
  部屋単位までインデックス面を作る、SUUMO より粒度の細かい設計。
- タイトルに `【募集中あり】` という**動的ステータス**を差し込んでいる
  （例: `【ホームズ】【募集中あり】メゾンヨシダ(川崎市高津区)の賃貸情報`）。
  CTR 最適化としては SUUMO の一歩先。
- **にもかかわらず、当該物件のアーカイブページは確認できない。**
  同名の朝霞物件には `b-19906289` が存在し、同じ高津区の「メゾンヨシダ」
  `b-36509925`、「ノイエハイム・高津」`b-36519725` も存在する。
  → 単純な取りこぼし。ここが最も分かりやすい空白地帯。

### 4-3. エリア一覧型（アットホーム / Yahoo!不動産 / CHINTAI / スマイティ / ニフティ / エイブル / ピタット / ホームメイト / カナリー ほか）

- 狙いは「川崎市高津区 賃貸」「溝の口駅 賃貸」といったミドル〜ビッグワード。
  建物名クエリは**そもそも設計の射程外**。
- 共通する面の取り方（＝自社サイトで真似できる型）:
  - 正規化ファセット URL（`kawasaki_takatsu-city`、駅コード `05098-st` など）
  - 派生ページの量産: 家賃相場 `/price/`、テーマ別 `/theme/12105/`（新築・築浅）、
    貸店舗 `/tempo/`、不動産会社一覧 `/estate/`、徒歩分数別（ホームメイト `/kt_68/`）
  - 鮮度シグナルのタイトル注入（カナリーの `【今週最新】`）
- 在庫が消えるとページも消えるため、指名クエリでは構造的に勝てない。

### 4-4. 非ポータル勢

- **itot（溝の口エリアガイド）**: 施設・生活情報でエリア周辺語を面で取る。
  物件ではなく「暮らし」側からエリア語に入ってくる型。
- **Yahoo!マップ / NAVITIME**: 建物名が POI 登録されると指名クエリでローカル面に出る。
  実際、朝霞・板橋の同名物件はここで拾われている。**当該物件は不在。**
- **口コミ型（マンションノート等）**: 当該物件は不在。

## 5. Bing 特有の論点

起点が Bing であることは、実は有利に働く。

1. **完全一致タイトルへの反応が素直**。Bing は固有名詞クエリにおいて、
   タイトル完全一致とドメイン権威を Google より直接的に評価する傾向がある。
   SUUMO が取れているのはまさにこの構造。逆に言えば、
   建物名を先頭に置いた title を持つ実体ページを作れば入れ替えは狙いやすい。
2. **IndexNow が使える**。Bing Webmaster Tools の URL 送信 / IndexNow により
   新規 URL を即時にインデックス投入できる。Google の待ち時間を回避できる。
3. **生成AIの引用元になる**。Bing インデックスは Copilot をはじめ複数の
   AI 検索のバックエンドとして使われる。今回の調査でも、AI 要約が
   「SUUMO に掲載されている」と答える構造になっていた。
   ここで 1 位を取ることは、AI 回答内での言及を取ることとほぼ同義。

## 6. 打ち手（優先度順）

### P0 — 建物専用ページを 1 枚作る（最優先・これだけで局面が変わる）

- **URL**: `/property/maison-yoneda/`
- **title**: `Maison Yoneda（メゾンヨネダ）｜川崎市高津区溝口5・高津駅徒歩5分の賃貸`
  - 3 系統の表記（英字 / カナ / 地名）を title に同居させ、表記ゆれを 1 枚で吸収する。
- **h1** も同形。本文冒頭で**同名異物件を明示的に切り分ける**:
  > 本ページは神奈川県川崎市高津区溝口5丁目の「Maison Yoneda」です。
  > 埼玉県朝霞市北原・東京都板橋区前野町の同名物件とは別の建物です。

  これは検索エンジンと AI に対するエンティティ解決の直接支援であり、
  §2 で見た混線に対して**誰も打っていない手**。
- **構造化データ**: `ApartmentComplex` + `PostalAddress` + `geo`、
  募集中の部屋は `RealEstateListing` / `Offer`。
  ポータル側がほぼ実装していない領域。
- **独自コンテンツ**（SUUMO の薄さに対する差分そのもの）:
  全室の間取り図、共用部・室内写真、設備一覧、
  高津駅・溝の口駅からの徒歩ルート、周辺生活情報、
  管理体制・修繕履歴、入居申込の流れと FAQ。

### P1 — ローカル / 地図面を埋める

- Google ビジネスプロフィール、Yahoo!プレイスに建物を登録し、住所表記を正規化。
- OpenStreetMap に建物名を登録（各種地図サービスへ波及する）。
- 同名異物件が POI を持ち、当該物件が持っていない現状は、そのまま機会損失。

### P2 — ポータルへの掲載でサイテーションを増やす

- HOME'S / アットホーム / いい部屋ネット等に掲載し、建物単位ページを生成させる。
- ただしポータルは**指名クエリを奪う競合でもある**。
  自社ページを先に立て、インデックスさせてから掲載する順序を守る。

### P3 — インデックス促進

- Bing Webmaster Tools 登録 + IndexNow で URL 即時送信。
- Google Search Console で URL 検査 → インデックス登録リクエスト。
- サイトマップに `lastmod` を正しく入れる。

### P4 — 計測

週次で以下の指名クエリの表示回数・クリック・平均掲載順位を GSC / BWT で追う。

- `Maison Yoneda`
